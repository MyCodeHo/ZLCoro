# wrk 最新压测结果（本机 8C16T i7-10700）

## epoll 后端（服务器 8 核）
- **最佳结果**: 872,830 QPS @ wrk 10 线程 / 1500 连接
- P50: 349µs, P99: 5.33ms
- 测试命令:
  ```bash
  ./http_server_v2 -c 8 -p 8080
  wrk -t10 -c1500 -d30s --latency http://127.0.0.1:8080/
  ```

其他观测：
- wrk 8 线程 / 1200 连接：838,750 QPS
- wrk 6 线程 / 800 连接：761,191 QPS
- wrk 4 线程 / 800 连接：624,086 QPS

## io_uring 后端（服务器 8 核）
- **最佳结果**: 761,900 QPS @ wrk 10 线程 / 1500 连接
- P50: 1.10ms, P99: 6.32ms
- 测试命令:
  ```bash
  ./http_server_v2 -c 8 -u -p 8081
  wrk -t10 -c1500 -d30s --latency http://127.0.0.1:8081/
  ```

其他观测：
- wrk 8 线程 / 1200 连接：736,201 QPS
- wrk 6 线程 / 800 连接：660,755 QPS
- wrk 4 线程 / 800 连接：560,384 QPS

## 结论与建议
1) **epoll 仍是本机最佳**：~87万 QPS，未达百万主要因 CPU 8C 限制 + wrk 与服务器争抢核心
2) **io_uring 仍低于 epoll**：原因是 workload 过于简单，io_uring 的提交/完成队列开销相对更高
3)  测试结果随着服务器线程数量增加而提升，符合线性扩展预期
